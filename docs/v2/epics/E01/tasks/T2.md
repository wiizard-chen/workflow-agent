# E01-T2 — Scaffold five private V2 workspace packages

## Objective
Create the five approved no-side-effect V2 package/application scaffolds with independent package identities and NodeNext builds.

## Scope
Create:
- `apps/workflowd` → `@pi-workflow/workflowd`
- `apps/workflow-worker` → `@pi-workflow/workflow-worker`
- `packages/v2-domain` → `@pi-workflow/v2-domain`
- `packages/v2-protocol` → `@pi-workflow/v2-protocol`
- `packages/v2-testkit` → `@pi-workflow/v2-testkit`

Each workspace must be private, `type=module`, have package exports to `dist`, an independent composite `tsconfig.json`, minimal `src/index.ts`, declaration output, and package-local build/typecheck/test script interfaces. Entry imports must have no process, timer, network, database, Git, Beads, Pi, or filesystem side effect.

## Dependency boundaries
- domain has no internal dependency;
- protocol may depend on domain;
- workflowd/worker may depend on domain+protocol but not each other;
- production packages must not depend on testkit;
- cross-package imports use package names/exports only.

## Non-goals
No actual domain entities, schemas, transport, daemon, Worker, or reusable testkit behavior beyond a typed empty boundary.

## Acceptance
- All five package identities are discovered by npm.
- `npm run build:v2` builds from a clean state and emits Node-executable ESM plus declarations.
- V1 tests/typecheck remain green.
- Compiled application entrypoints exit without persistent effects.

## Task-stage gate
```bash
npm run test:v1 && npm run typecheck:v1 && npm run build:v2 && git diff --check
```

## Evidence
Return workspace list, build output summary, changed files, and commit SHA.
