# E01-T4 — Isolated wfpi and Pi Git-package compatibility harness

## Objective
Prove that npm workspaces do not break local-source `wfpi` or installed Git Pi-package behavior.

## Scope
Implement `scripts/test-v2-package-compat.mjs` with:

### Local-source mode
- temporary target Git repository;
- temporary `PI_CODING_AGENT_DIR` and `PI_CODING_AGENT_SESSION_DIR`;
- isolated installation/loading of `npm:pi-subagents` in that configuration;
- `PI_SKIP_VERSION_CHECK=1`, `PI_TELEMETRY=0`, no session persistence;
- no-model RPC/diagnostic assertions for workflow/cache extensions and `/wf` registration;
- assertion that isolated pi-subagents consumes `PI_SUBAGENT_EXTRA_AGENT_DIRS` and discovers namespaced workflow agents.

### Candidate clone parity mode
- clone the exact candidate commit into a temporary directory;
- run `npm install --omit=dev` with no custom `npmCommand`;
- load the cloned root under isolated Pi configuration;
- assert core extensions/skills separately from pi-subagents agent discovery.

### Actual Pi Git-package mode
- accept a `git:github.com/wiizard-chen/workflow-agent@<candidate-sha>` source;
- use isolated `pi install` after isolated pi-subagents installation;
- set `GIT_TERMINAL_PROMPT=0` and forbid SSH/credential/user-config fallback;
- assert the installed path and deterministic resource discovery;
- clean all temporary state.

## Non-goals
No model call, provider credential, GitHub API credential, merge, daemon, or V2 Runtime.

## Acceptance
- Local-source and clone-parity modes pass before remote publication.
- Actual Git-package mode passes after this branch's candidate SHA is pushed to the authorized origin branch.
- Missing isolated pi-subagents, package discovery, omit-dev behavior, or cleanup fails closed.
- User Pi settings/models/sessions/packages remain byte-for-byte untouched.

## Task-stage gate
```bash
npm run check && node scripts/test-v2-package-compat.mjs --candidate "$PWD" --mode clone-parity && git diff --check
```

The actual Pi Git-package gate is executed by the manager after pushing the authorized E01 branch and is required before task closure/final delivery.

## Evidence
Return isolated paths, discovery assertions, user-config before/after hashes, command outputs, and commit SHA.
