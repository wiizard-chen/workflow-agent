> E08 is a local Runtime exclusivity primitive. It does not schedule work,
> launch workers, grant business authority, or replace the E05 journal. Every
> accepted lease operation is durable and fenced; no external effect is
> authorized by this document.

## 1. Authority and dependency boundary

E08 is subordinate to the Initiative Charter, Architecture RFC, Initial Epic
Map, E04 persistence contract, and E05 journal transaction seam. E04 owns
SQLite initialization, WAL policy, migration locking, schema inspection, and
backup/recovery. E05 owns command/event/outbox facts. E08 owns only Runtime
lease records, heartbeat expiry, fencing-token allocation, and the typed guard
that proves a sensitive operation is still authorized by a current lease.

The lease table is an E08 schema extension at migration version 3 on the same
Runtime database as E05. E08 must open that database with the static E04 + E05
 + E08 manifest, and must never accept caller-supplied SQL or migration
descriptors. The public package exposes neither a native SQLite handle nor a
generic transaction callback.

## 2. Problem and bounded result

Several Runtime actors may outlive a daemon connection or be delayed by a
crash. A new owner must be able to take a resource while an old process is
still alive, and the old process must be unable to mutate state after takeover.
E08 delivers a small durable primitive that can:

1. allocate one lease for one named resource, with an opaque lease ID and a
   strictly increasing fencing token;
2. renew/heartbeat only the current lease owner and token while its TTL is
   valid;
3. revoke a current lease and make it immediately unusable;
4. reacquire an expired or revoked resource atomically, incrementing the
   durable token even after daemon/database restart; and
5. guard a sensitive operation using resource, lease ID, owner, token, and
   current time without exposing a mutation-capable SQL surface.

The default policy values are a 5-second heartbeat interval and 20-second
lease TTL, as recommended by the Architecture RFC. They are policy defaults,
not protocol constants: callers may select bounded positive values for tests or
future policy layers. E08 does not decide which actor should be scheduled.

## 3. Recommended implementation decisions

### 3.1 Resource and record identity

Resource kinds are a closed allowlist for the MVP:

    epic | delivery-unit | integration | release | product-session | repository

Resource IDs and owner IDs are non-empty NUL-free UTF-8 strings of at most 256
bytes. The database primary key is `(resource_kind, resource_id)`, so there is
at most one current row for a resource. `leaseId` is an opaque lower-case
stable identifier generated by the store, not a caller-provided token.

The record contains `resourceKind`, `resourceId`, `leaseId`, `ownerId`,
`fencingToken`, `issuedAtEpochMs`, `heartbeatAtEpochMs`, `expiresAtEpochMs`,
and `status` (`active` or `revoked`). Timestamps are safe non-negative integer
epoch milliseconds; `expiresAtEpochMs` must be greater than
`heartbeatAtEpochMs`.

### 3.2 Atomic allocation and fencing

`acquire` runs under the E04 migration lock. If the current row is active and
unexpired, it returns `lease_held` without changing any bytes. If it is
expired or revoked, it replaces the current lease ID/owner/timestamps and
increments `fencingToken` by exactly one. A fresh resource starts at token 1.
The update and the returned record commit together; a failed transaction
cannot consume a token.

`renew` and `heartbeat` require the exact current lease ID, owner, fencing
token, and a non-expired current row. They extend expiry from the heartbeat
timestamp by the requested TTL and never decrease a timestamp or token.

`revoke` requires the current lease credentials and records `revoked` with the
revocation time. Revoke is idempotent for the same credentials and returns the
unchanged revoked record; stale credentials receive a typed fencing rejection.

### 3.3 Guard semantics

`guard` is read-only and checks all of the following in one database snapshot:

- resource kind and ID match the row;
- lease ID, owner ID, and fencing token match exactly;
- row status is `active`;
- supplied `nowEpochMs` is within the lease interval; and
- no earlier revocation or replacement has superseded the row.

The guard returns a frozen `LeaseProof` containing the exact current record and
never accepts a caller-supplied `active` boolean as authority. A caller that
needs a state change must perform the guard and its own typed operation in one
E08 transaction; E08 does not expose arbitrary callbacks or claim to make a
cross-table business mutation atomic.

### 3.4 Heartbeat service

`createHeartbeat` returns a bounded controller for one lease. `beat` performs
one synchronous renewal; `start` validates one beat before scheduling future
beats at an interval no shorter than 100 ms; `stop` clears the timer and is
idempotent. The controller enters `failed` with a typed, observable rejection
after the first renewal failure and never renews a revoked, expired, or
replaced lease. Tests use an injected clock and explicit `beat` calls; no timer
is started during import or store open.

### 3.5 Schema extension and persistence

The E08 migration creates exactly one table:

    workflow_runtime_lease(
      resource_kind TEXT NOT NULL CHECK (resource_kind IN ('epic', 'delivery-unit', 'integration', 'release', 'product-session', 'repository')),
      resource_id TEXT NOT NULL,
      lease_id TEXT NOT NULL UNIQUE,
      owner_id TEXT NOT NULL,
      fencing_token INTEGER NOT NULL CHECK (fencing_token > 0),
      status TEXT NOT NULL CHECK (status IN ('active', 'revoked')),
      issued_at_ms INTEGER NOT NULL CHECK (issued_at_ms >= 0),
      heartbeat_at_ms INTEGER NOT NULL CHECK (heartbeat_at_ms >= 0),
      expires_at_ms INTEGER NOT NULL CHECK (expires_at_ms > heartbeat_at_ms),
      revoked_at_ms INTEGER,
      CHECK ((status = 'active' AND revoked_at_ms IS NULL) OR (status = 'revoked' AND revoked_at_ms IS NOT NULL)),
      PRIMARY KEY (resource_kind, resource_id)
    )

The schema descriptor, migration digest, backup validation, and reopen path
must all recognize E04, E05, and E08 in order. A database opened by E05 alone
must remain valid at version 2; opening through E08 upgrades it to version 3.
The journal facade therefore provides an explicit composite-open option for
callers that need E05 and E08 on the same database; a v2-only opener fails
closed on a v3 database rather than silently ignoring the lease table.

## 4. Frozen public boundary

The workflowd entrypoint may expose only the following typed facade and data
types. It must not expose a native SQLite connection, SQL, raw row objects,
timer handles, mutable buffers, or callbacks that can perform arbitrary I/O.

    type LeaseOptions = Readonly<{
      readonly runtimeRoot: string;
      readonly databasePath: string;
      readonly backupDirectory?: string;
      readonly mode?: "read-only" | "read-write";
      readonly now: () => number;
      readonly heartbeatIntervalMs?: number;
      readonly leaseTtlMs?: number;
    }>;

    type LeaseRequest = Readonly<{
      readonly resourceKind: LeaseResourceKind;
      readonly resourceId: string;
      readonly ownerId: string;
    }>;

    type LeaseCredentials = Readonly<LeaseRequest & {
      readonly leaseId: string;
      readonly fencingToken: number;
    }>;

    type LeaseRecord = Readonly<LeaseCredentials & {
      readonly issuedAtEpochMs: number;
      readonly heartbeatAtEpochMs: number;
      readonly expiresAtEpochMs: number;
      readonly status: "active" | "revoked";
      readonly revokedAtEpochMs?: number;
    }>;

    type HeartbeatController = Readonly<{
      readonly beat: () => LeaseResult<LeaseRecord>;
      readonly start: () => LeaseResult<true>;
      readonly stop: () => void;
      readonly status: "idle" | "running" | "stopped" | "failed";
      readonly failure: LeaseRejection | undefined;
    }>;

    type LeaseStore = Readonly<{
      readonly acquire: (request: unknown) => LeaseResult<LeaseRecord>;
      readonly renew: (credentials: unknown) => LeaseResult<LeaseRecord>;
      readonly heartbeat: (credentials: unknown) => LeaseResult<LeaseRecord>;
      readonly revoke: (credentials: unknown) => LeaseResult<LeaseRecord>;
      readonly guard: (credentials: unknown) => LeaseResult<LeaseProof>;
      readonly createHeartbeat: (credentials: unknown) => LeaseResult<HeartbeatController>;
      readonly inspect: () => LeaseResult<LeaseInspection>;
      readonly close: () => void;
    }>;

Successful records, proofs, inspections, and rejection objects are independent
recursively frozen snapshots. Every rejection is typed and secret-free. The
public diagnostic guard always uses the store-owned clock; callers cannot pass
an earlier time to revive an expired lease. Later Runtime writers use a
non-public `assertCurrentLeaseInTransaction` seam while holding the same
`BEGIN IMMEDIATE` lock as their typed mutation, avoiding a guard/commit TOCTOU.

## 5. Acceptance criteria

- AC-001 Import/open safety: importing E08 has no filesystem effect; open uses
  only the explicit E04 paths and does not touch V1 `.workflow` output.
- AC-002 Schema/restart: E08 registers one exact version-3 extension, upgrades
  an E05 database, reopens it, and preserves the highest fencing token.
- AC-003 Allocation: a resource has at most one active lease; active unexpired
  acquisition is rejected; expired/revoked acquisition increments the token
  exactly once and commits atomically.
- AC-004 Renewal/heartbeat: only current credentials renew; timestamps move
  forward within bounded TTL; a failed renewal never partially updates a row.
- AC-005 Fencing/guard: stale lease ID, owner, token, resource, revoked state,
  or expired time is rejected; the current lease produces a frozen proof.
- AC-006 Revoke: current revoke is durable and immediate; stale/replayed revoke
  cannot revoke a newer lease; repeated close is harmless.
- AC-007 Heartbeat controller: an initial beat is validated before scheduling;
  explicit beats and timer lifecycle are bounded, idempotent, expose a typed
  failure state, and leave no active timer after stop/close.
- AC-008 Read-only/hostile/fault boundary: read-only mode never writes;
  accessors, proxies, symbols, malformed credentials, clock failures,
  symlink/path replacement, migration failure, and transaction failure reject
  before partial state; diagnostics contain no secrets.
- AC-009 Public boundary and gates: no SQL/native handle/timer escape; V1/V2
  tests, typecheck, boundary validation, Bundle check, and diff check pass.

## 6. Attack and fault matrix

| ID | Fault/attack | Expected invariant |
|---|---|---|
| AM-01 | two acquires race for one resource | one winner; one typed `lease_held`; no token gap |
| AM-02 | stale owner after re-grant | guard/renew/revoke reject old lease ID or token |
| AM-03 | daemon closes/reopens after grant | lease and highest token remain durable |
| AM-04 | heartbeat at/after expiry | no resurrection; typed `lease_expired` |
| AM-05 | revoke followed by replay | revoked row cannot be used or double-counted |
| AM-06 | malformed object/accessor/proxy/symbol | fail closed before SQL or filesystem mutation |
| AM-07 | injected transaction/migration failure | rollback preserves prior row and token |
| AM-08 | read-only, symlink, broad mode, or path escape | no mutation; typed diagnostic |
| AM-09 | clock moves backwards or exceeds safe bounds | reject invalid clock; stored times never decrease |
| AM-10 | heartbeat timer stop/close race | no leaked timer or post-close renewal |

## 7. Non-goals and stop boundary

E08 does not implement scheduler policy or capacity, worker processes, Pi SDK
sessions, task/step transitions, Product approval, access grants, sandboxing,
Git/GitHub/Beads effects, network calls, lease history retention, distributed
consensus, or cross-machine clock synchronization. E09 consumes the lease to
host a worker; E14 consumes it for allocation policy; E16/E27 consume it for
workspace and GitHub operations.
