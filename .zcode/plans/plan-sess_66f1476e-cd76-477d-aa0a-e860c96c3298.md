# 方案:/execute 加可选 PRD 路径参数

## 目标
`/execute` 接受可选的 PRD 文件路径参数。不传时保持现状(用当前 `wf` 绑定的 PRD);传了就用指定 PRD,并自动建新 epic。

用法:
```
/execute                    # 现状:用当前需求的 prd.md
/execute ./prd.md           # 新增:用指定 PRD(自动建新 epic)
/execute /abs/path/prd.md   # 绝对路径也行
```

## 你的场景
前面在主 session 讨论多个需求(每个可能手写或 `/wf prd` 生成各自 PRD),之后用 `/execute <路径>` 指定跑哪一个。execute 保持同步阻塞(不动 spawn 机制)。

## 改动点(都在 extensions/workflow.ts)

### 1. cmdExecute 加 args 参数 + 路径解析
仿照 cmdNew 的模式(workflow.ts:273-279):
- 签名改 `cmdExecute(pi, ctx, args: string = "")`
- 解析:`const prdPathArg = args.trim().replace(/["']/g, "")`
- 空字符串 = 用默认 `reqPath(wf, "prd.md")`(现状)
- 非空 = `path.resolve(prdPathArg)` 解析成绝对路径

### 2. 外部 PRD 时自动建新 epic
当传了外部 PRD 路径时(且与当前 wf 的 prd.md 不同):
- 用 PRD 文件名派生 epic 标题:`path.basename(absPrd, ".md")`
- `bd.create(wf.repo, { title, type: "epic" })` 建新 epic
- 把这个新 epicId 存到一个局部变量,传给经理

### 3. 经理上下文传递(workflow.ts:407-421 spawn 调用)
经理进程需要知道用哪个 PRD + 哪个 epic。两个渠道都传(belt and suspenders,和现有 WF_REQID 一样):
- **env 变量**:加 `WF_PRD_PATH=<absPrd>` 和 `WF_EPIC_ID=<newEpicId>` 到 mgrEnv
- **prompt 注入**:`loadManagerPrompt()` 已有"运行上下文"块(workflow.ts:377),把 PRD 文件路径和 epicId 改成实际的(覆盖默认的 reqPath(wf,"prd.md"))

### 4. PRD 存在性检查适配(workflow.ts:390)
当前:`if (!fs.existsSync(reqPath(wf, "prd.md"))) { 报错 }`
改成:用解析后的实际 PRD 路径检查存在性(外部 PRD 时检查外部文件)

### 5. 调用处传参(两处)
- workflow.ts:652 `case "execute": await cmdExecute(pi, ctx, rest); break;`(传 rest)
- workflow.ts:679 独立 execute 命令的 handler:把 `_args` 传进去

### 6. 经理侧:split_prd_to_tasks 用传入的 PRD 路径 + epicId
- split_prd_to_tasks 工具(workflow.ts:457):PRD 路径 fallback 链改为 `params.prd_path || process.env.WF_PRD_PATH || reqPath(wf,"prd.md")`
- epicId 用法(workflow.ts:488 `parent: wf!.epicId`):改为优先用 `process.env.WF_EPIC_ID || wf!.epicId`
- run_test 建 bug 的 parent(workflow.ts:565):同样改

### 7. help 文本 + 提示语更新
- workflow.ts:664 的命令列表:`/execute [prd路径]`
- cmdExecute 启动 notify:说明用的是哪个 PRD + epic

## 不做的事
- ❌ 不改同步阻塞机制(你说 execute 就在主 session 执行)
- ❌ 不动 dev-pool / reasonix(执行层不变)
- ❌ 不动 /wf new(单例锁不动)
- ❌ 不改 /wf execute 以外的命令

## 验证
- `/execute`(无参):行为完全不变(用当前 wf 的 prd.md)
- `/execute ./some-prd.md`:用指定 PRD,自动建新 epic,task/bug 挂新 epic,经理读指定 PRD
- 边界:PRD 文件不存在 → 报错;路径有引号 → 剥离;相对路径 → 基于 ctx.cwd 解析
- node --experimental-strip-types 验证 workflow.ts 语法
