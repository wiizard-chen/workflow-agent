# 方案:/wf bug 改进 — 自动拆分多 bug

## 目标
`/wf bug <一段描述>` 时,用 glm-5.2 分析描述,如果是多个独立问题(如"首先/其次/另外"),自动拆成多个 bd bug,每个一个规格文件。同时修文件名超长问题(slug 截断)。

## 改动点(extensions/workflow.ts cmdBug)

### 1. cmdBug 改用 split 模型拆分
当前:一句话直接建一个 bug。
改成:
- 用 `runStageText(pi, ctx, CONFIG.roles.split, ...)` 让 deepseek-pro 分析描述
- prompt:"分析这段 bug 描述,如果是多个独立问题就拆开。输出严格 JSON:{"bugs":[{"title":"短标题","desc":"具体描述"}]}"
- 如果只有 1 个问题,JSON 里就 1 个 bug;多个就多个

### 2. 循环建 bug
拆分后,对每个 bug:
- slug(title).slice(0, 30) 截断文件名(修超长问题)
- bd create --type=bug --parent=<epic> --notes="规格文件:<路径>"
- 写规格文件(标题 + 具体描述 + 验收)

### 3. 结果汇报
notify 显示建了几个 bug + 各自 id + 提示 /execute

### 4. cmdBug 需要 pi 参数(调 runStageText)
当前 cmdBug(ctx, args) → 改成 cmdBug(pi, ctx, args)
dispatcher 调用处相应改:`case "bug": cmdBug(pi, ctx, rest);`

## 不做的事
- ❌ 不加交互式(你选了自动拆分,不是交互)
- ❌ 不改 /execute(那是另一个问题,需要你贴报错)
- ❌ 不改 manager.md(bug 检查逻辑已就绪)

## 验证
- `/wf bug next 报错` → 1 个问题 → 建 1 个 bug
- `/wf bug 首先 next 报错,其次导航栏没用` → 2 个问题 → 建 2 个 bug
- 文件名截断到 30 字符内
